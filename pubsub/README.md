# pubsub

Generic publish/subscribe abstraction for Go services, with concrete Kafka, RabbitMQ, and Redis backends.

All backends satisfy the same `pubsub.Publisher` and `pubsub.Consumer` interfaces. Swapping brokers is a wiring change — no service-layer code changes.

---

## Package layout

```
pubsub/             ← Publisher, Consumer interfaces; Message, Handler types
pubsub/kafka/       ← Kafka backend  (segmentio/kafka-go)
pubsub/rabbitmq/    ← RabbitMQ backend (amqp091-go)
pubsub/redis/       ← Redis Pub/Sub backend (go-redis/v9)
pubsub/mocks/       ← MockPublisher, MockConsumer (generated — do not edit)
```

---

## SOLID design

| Principle | Applied here |
|---|---|
| **SRP** | `Publisher` and `Consumer` are separate interfaces — sending and receiving are different responsibilities |
| **OCP** | New backends (NATS, SQS, Redis Streams) can be added as new sub-packages without touching existing code |
| **LSP** | Any backend can substitute another at the wiring layer — the service layer works unchanged |
| **ISP** | A service that only publishes depends on `Publisher` only; a worker that only consumes depends on `Consumer` only |
| **DIP** | Service layers depend on `pubsub.Publisher` / `pubsub.Consumer`, not on `*kafka.Writer` or `*amqp091.Connection` |

## Interfaces

```go
// Publisher sends messages to a named topic.
type Publisher interface {
    Publish(ctx context.Context, topic string, msg Message) error
    Close() error
}

// Consumer receives messages from a named topic within a consumer group.
type Consumer interface {
    Subscribe(ctx context.Context, topic, group string, handler Handler) error
    Close() error
}

// Handler processes a received message.
// Return nil to acknowledge; return error to nack/requeue.
type Handler func(ctx context.Context, msg Message) error
```

### `Message`

```go
type Message struct {
    ID      string            // unique ID; generated by backend if empty on Publish
    Key     string            // partition key (Kafka) or routing key (RabbitMQ)
    Payload []byte            // raw body
    Headers map[string]string // arbitrary metadata
}
```

### Ack / Nack contract

| Handler return | Kafka | RabbitMQ |
|---|---|---|
| `nil` | offset committed | `ack` |
| `error` | offset NOT committed (redelivered on restart) | `nack` + requeue |

## Kafka backend (`pubsub/kafka`)

```go
import "github.com/labspangaea/go-lib/pubsub/kafka"
```

### Publisher

```go
pub := kafka.NewPublisher(
    []string{"kafka:9092"},
    kafka.WithMaxAttempts(5), // optional; default 3
)
defer pub.Close()

err := pub.Publish(ctx, "orders.created", pubsub.Message{
    Key:     order.ID,          // routes to a stable partition for this order
    Payload: orderJSON,
    Headers: map[string]string{"source": "order-service"},
})
```

**Defaults:**
- LeastBytes balancer (routes to partition with fewest buffered bytes)
- `RequireAll` acks (leader + all in-sync replicas confirm)
- Synchronous — `Publish` blocks until broker confirms

### Consumer

```go
con := kafka.NewConsumer(
    []string{"kafka:9092"},
    kafka.WithLastOffset(), // optional; default reads from first unread offset
)
defer con.Close()

// Subscribe is blocking — run it in a goroutine or use a long-lived context.
ctx, cancel := context.WithCancel(context.Background())
defer cancel()

if err := con.Subscribe(ctx, "orders.created", "invoice-service", func(ctx context.Context, msg pubsub.Message) error {
    return processOrder(ctx, msg.Payload)
}); err != nil {
    log.Fatal(err)
}
```

**At-least-once delivery:** the offset is committed only when the handler returns `nil`.
A handler error leaves the offset uncommitted — the message is redelivered when the consumer restarts.

**Stopping:** cancel the context OR call `con.Close()` from another goroutine.

## RabbitMQ backend (`pubsub/rabbitmq`)

```go
import "github.com/labspangaea/go-lib/pubsub/rabbitmq"
```

### Connection

Manage the connection yourself and pass it to both Publisher and Consumer.
The connection should be shared and re-established on disconnect:

```go
conn, err := amqp091.Dial("amqp://guest:guest@rabbitmq:5672/")
if err != nil {
    log.Fatal(err)
}
defer conn.Close()
```

### Publisher

```go
pub, err := rabbitmq.NewPublisher(conn, "orders",
    rabbitmq.WithExchangeType(rabbitmq.ExchangeDirect), // default
)
if err != nil {
    log.Fatal(err)
}
defer pub.Close()

err = pub.Publish(ctx, "orders.created", pubsub.Message{
    ID:      uuid.New().String(),
    Payload: orderJSON,
    Headers: map[string]string{"source": "order-service"},
})
```

`topic` in `Publish` = routing key. The exchange is declared as **durable** automatically.

### Consumer

```go
con := rabbitmq.NewConsumer(conn, "orders",
    rabbitmq.WithPrefetchCount(10), // optional; default 1
)

if err := con.Subscribe(ctx, "orders.created", "invoice-service",
    func(ctx context.Context, msg pubsub.Message) error {
        return processOrder(ctx, msg.Payload)
    },
); err != nil {
    log.Fatal(err)
}
```

**Topology declared automatically per `Subscribe` call:**

```
Publisher → exchange "orders" (direct, durable)
                ↓ routing key: "orders.created"
Consumer  → queue "invoice-service" (durable)
```

Multiple services can bind to the same exchange with different routing keys, or the same routing key with different queue names (fan-out pattern).

### Exchange types

| Constant | AMQP type | `topic` in Publish maps to |
|---|---|---|
| `ExchangeDirect` | `direct` | exact routing key match |
| `ExchangeTopic` | `topic` | pattern match (`orders.*`, `#`) |
| `ExchangeFanout` | `fanout` | ignored — all queues receive every message |

## Redis backend (`pubsub/redis`)

```go
import "github.com/labspangaea/go-lib/pubsub/redis"
```

Redis Pub/Sub is a **fire-and-forget broadcast**: messages are delivered only to subscribers active at the moment of publish. There is no persistence, no consumer group, and no redelivery on failure.

Use this backend for low-latency fanout — live notifications, cache invalidation signals, real-time dashboards. For durable, at-least-once delivery use the Kafka or RabbitMQ backends.

### Publisher

```go
client := goredis.NewClient(&goredis.Options{Addr: "redis:6379"})

pub := redis.NewPublisher(client)
defer pub.Close() // no-op — client is owned by the caller

err := pub.Publish(ctx, "notifications.user", pubsub.Message{
    ID:      uuid.New().String(),
    Payload: notifJSON,
    Headers: map[string]string{"source": "notification-service"},
})
```

`topic` in `Publish` maps directly to a Redis channel name. The message is JSON-encoded so all fields (ID, Key, Headers, Payload) survive the round-trip.

### Consumer

```go
con := redis.NewConsumer(client)

// Subscribe is blocking — run it in a goroutine or use a long-lived context.
ctx, cancel := context.WithCancel(context.Background())
defer cancel()

if err := con.Subscribe(ctx, "notifications.user", "" /* group unused */, func(ctx context.Context, msg pubsub.Message) error {
    return deliverNotification(ctx, msg.Payload)
}); err != nil {
    log.Fatal(err)
}
```

**Broadcast semantics:** every active subscriber receives every message. The `group` parameter is accepted for interface compatibility but has no effect — Redis Pub/Sub has no consumer-group concept.

**No ack/nack:** the handler return value is noted but has no broker-level effect. Failed messages are not requeued.

**Stopping:** cancel the context. The subscription channel closes and `Subscribe` returns `nil`.

## Wiring in a service

Depend on the interface, inject the backend at the application boundary:

```go
// order/service.go
type OrderService struct {
    pub pubsub.Publisher
}

func NewOrderService(pub pubsub.Publisher) *OrderService {
    return &OrderService{pub: pub}
}

func (s *OrderService) Create(ctx context.Context, o Order) error {
    // ... business logic ...
    return s.pub.Publish(ctx, "orders.created", pubsub.Message{
        Key:     o.ID,
        Payload: marshal(o),
    })
}
```

```go
// main.go — wire Kafka
pub := kafka.NewPublisher([]string{"kafka:9092"})
defer pub.Close()

svc := order.NewOrderService(pub)
```

```go
// main.go — wire RabbitMQ (no code change in OrderService)
pub, _ := rabbitmq.NewPublisher(conn, "orders")
defer pub.Close()

svc := order.NewOrderService(pub)
```

## Graceful shutdown

Graceful shutdown means: **stop fetching new messages, finish the current one, commit/ack it, then close resources**. Aborting mid-message risks duplicate processing on restart (at-least-once delivery requires the message to be redelivered).

### How it works in this library

Both backends use `context.WithoutCancel` when calling the handler:

```
ctx cancelled (shutdown signal)
    │
    ├── FetchMessage / select loop exits immediately
    │
    └── Handler already running:
            receives context.WithoutCancel(ctx)
            → its DB/HTTP calls are NOT aborted
            → completes normally
            → Ack / CommitOffset succeeds
            → Subscribe returns nil
```

The shutdown signal stops **fetching** new messages. It does not abort the message **being processed**.

### Shutdown sequence

```go
// 1. Signal received (SIGTERM / SIGINT)
cancel()            // stop the fetch loop

// 2. Wait for Subscribe to return (current handler finishes + ack/commit)
wg.Wait()

// 3. Close broker clients
publisher.Close()
consumer.Close()

// 4. Close the connection (RabbitMQ only — Kafka has no shared connection)
conn.Close()
```

### Full example with OS signal handling

```go
package main

import (
    "context"
    "log"
    "os"
    "os/signal"
    "sync"
    "syscall"

    "github.com/labspangaea/go-lib/pubsub"
    "github.com/labspangaea/go-lib/pubsub/kafka"
)

func main() {
    pub := kafka.NewPublisher([]string{"kafka:9092"})
    con := kafka.NewConsumer([]string{"kafka:9092"})

    ctx, cancel := context.WithCancel(context.Background())
    var wg sync.WaitGroup

    // Start consumer in background
    wg.Add(1)
    go func() {
        defer wg.Done()
        if err := con.Subscribe(ctx, "orders.created", "invoice-service", handleOrder); err != nil {
            log.Println("subscribe error:", err)
        }
    }()

    // Wait for OS shutdown signal
    quit := make(chan os.Signal, 1)
    signal.Notify(quit, syscall.SIGTERM, syscall.SIGINT)
    <-quit
    log.Println("shutdown signal received — draining...")

    // Stop fetch loop; in-flight handler completes before Subscribe returns
    cancel()
    wg.Wait()

    // Safe to close now: no handler is running, all offsets committed
    _ = con.Close()
    _ = pub.Close()

    log.Println("shutdown complete")
}

func handleOrder(ctx context.Context, msg pubsub.Message) error {
    // ctx is context.WithoutCancel — DB/HTTP calls here are NOT cancelled on shutdown
    return processOrder(ctx, msg.Payload)
}
```

### Kafka — commit timeout

After the handler returns, the offset commit uses a separate timeout context
(default 5 s) so it succeeds even when the main context is already cancelled:

```go
con := kafka.NewConsumer(brokers,
    kafka.WithCommitTimeout(10*time.Second), // extend if broker is slow
)
```

If the commit times out during shutdown, the message is redelivered on the next
consumer start — this is expected at-least-once behaviour, not data loss.

### RabbitMQ — connection vs channel lifecycle

```go
conn, _ := amqp091.Dial("amqp://guest:guest@rabbitmq:5672/")

pub, _ := rabbitmq.NewPublisher(conn, "orders") // owns its channel
con    := rabbitmq.NewConsumer(conn, "orders")   // creates a channel per Subscribe

// Shutdown order matters:
cancel()          // 1. stop consumer fetch loop
wg.Wait()         // 2. wait for handler + ack
_ = con.Close()   // 3. no-op (channel already closed by Subscribe's defer)
_ = pub.Close()   // 4. close publisher channel
_ = conn.Close()  // 5. close connection LAST — after all channels are done
```

Closing the connection before the channel causes the channel's publish/consume
to return an error. Always close channels first, connection last.

### Multiple consumers

Run each `Subscribe` in its own goroutine; all share the same `cancel`:

```go
ctx, cancel := context.WithCancel(context.Background())
var wg sync.WaitGroup

for _, topic := range []string{"orders.created", "orders.cancelled"} {
    wg.Add(1)
    go func(t string) {
        defer wg.Done()
        _ = con.Subscribe(ctx, t, "invoice-service", handler)
    }(topic)
}

<-quit
cancel()   // stops all Subscribe loops simultaneously
wg.Wait()  // each drains its current message independently
```

## Choosing a broker

| | Kafka | RabbitMQ | Redis Pub/Sub |
|---|---|---|---|
| **Delivery model** | Pull (consumer controls pace) | Push (broker delivers) | Push (broadcast) |
| **Retention** | Configurable (days/weeks) | Until acked | None — fire and forget |
| **Replay** | Yes — seek to any offset | No | No |
| **Ordering** | Per-partition (use `Key`) | Per-queue (single consumer) | No guarantee |
| **Throughput** | Very high (millions/s) | High (tens of thousands/s) | Very high (in-memory) |
| **Routing** | Topic + partition key | Exchange type + routing key | Channel name (exact match) |
| **Consumer groups** | Yes | Yes (queue name) | No — all subscribers receive every message |
| **Ack / Nack** | Offset commit | AMQP ack/nack | None |
| **Best for** | Event streams, audit logs, high throughput | Task queues, RPC, complex routing | Live notifications, cache invalidation, fanout |

**Use Kafka** when you need replay, high throughput, or ordered event streams.
**Use RabbitMQ** when you need flexible routing, request/reply, or per-message ack/nack semantics.
**Use Redis** when you need low-latency broadcast with no durability requirement — live presence, invalidation signals, real-time dashboards.
